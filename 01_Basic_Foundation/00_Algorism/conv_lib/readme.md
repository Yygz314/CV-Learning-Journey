# 自建卷积算法库完整教程

## 项目简介

这是一个**从零开始、无任何第三方依赖**的纯 C++ 卷积算法库实现。本项目不仅包含基础的 2D 单通道卷积算法，更重要的是完整展示了**C++ 自建库并调用**的标准流程，是学习计算机视觉基础算法和 C++ 工程化实践的绝佳入门案例。

本项目实现了最基础的 Valid 模式（无填充、步长 = 1）单通道卷积，代码简洁易懂，每一行都有详细注释，适合初学者逐行理解卷积计算的本质。

## 项目结构详解

```
conv_lib/
├── convolution.h    # 库的头文件（对外接口声明）
├── convolution.cpp  # 库的实现文件（卷积算法核心逻辑）
└── main.cpp         # 库的调用测试文件
```

### 各文件作用与设计原则

#### 1. `convolution.h` - 头文件（接口层）

**核心作用**：对外暴露库的公共接口，告诉编译器和调用者 "这个库提供了什么功能"。

**为什么需要头文件？**

- 实现**接口与实现分离**：调用者只需要知道函数声明，不需要知道具体实现细节
- 解决多文件编译的依赖问题：当多个文件都要调用同一个函数时，只需要包含同一个头文件
- 防止头文件重复包含：使用`#ifndef/#define/#endif`保护宏

**头文件里应该写什么？**

- 函数声明
- 宏定义
- 结构体 / 类声明
- 常量定义

**头文件里绝对不能写什么？**

- 函数的具体实现（会导致多重定义错误）
- 全局变量的定义

#### 2. `convolution.cpp` - 实现文件（逻辑层）

**核心作用**：包含卷积算法的具体实现代码，是库的核心部分。

**实现文件的特点**：

- 必须包含对应的头文件：`#include "convolution.h"`
- 所有在头文件中声明的函数，都必须在这里实现
- 可以包含私有的辅助函数和变量，这些不会对外暴露

#### 3. `main.cpp` - 调用文件（应用层）

**核心作用**：测试和使用我们编写的卷积库，不包含任何卷积算法的实现代码。

**调用库的标准流程**：

1. 包含库的头文件：`#include "convolution.h"`
2. 准备输入数据和卷积核
3. 调用头文件中声明的卷积函数
4. 处理和输出结果

## 快速开始

### 前置条件

确保你的系统已经安装了 C++ 编译器：

- Windows：推荐安装 MinGW-w64（添加到系统环境变量）
- Linux：系统自带 g++
- Mac：安装 Xcode 命令行工具：`xcode-select --install`

### 编译运行（两种方式任选）

#### 方式一：直接编译（最简单，适合新手）

将库文件和主文件一起编译，生成可执行程序。

**Windows（CMD/PowerShell）**

```bash
# 编译：将main.cpp和convolution.cpp一起编译成conv_test.exe
g++ main.cpp convolution.cpp -o conv_test

# 运行：Windows下直接输入可执行文件名
conv_test
```

**Linux/Mac**

```bash
# 编译
g++ main.cpp convolution.cpp -o conv_test

# 运行：Linux/Mac下需要加./前缀
./conv_test
```

#### 方式二：编译成静态库（正式库用法，推荐）

先将卷积算法编译成独立的静态库文件，再将主文件与静态库链接。

**Windows（CMD/PowerShell）**

```bash
# 第一步：编译库文件为目标文件（只编译不链接）
g++ -c convolution.cpp -o convolution.o

# 第二步：将目标文件打包成静态库libconv.a
ar rcs libconv.a convolution.o

# 第三步：编译主文件并链接静态库
# -L. 表示在当前目录下搜索库文件
# -lconv 表示链接名为libconv.a的库
g++ main.cpp -L. -lconv -o conv_test

# 运行
conv_test
```

**Linux/Mac**

```bash
# 编译静态库
g++ -c convolution.cpp -o convolution.o
ar rcs libconv.a convolution.o

# 链接并运行
g++ main.cpp -L. -lconv -o conv_test
./conv_test
```

## 核心算法原理详解

### 卷积计算的本质

卷积的本质是**滑动窗口加权求和**：让卷积核在输入图像上从左到右、从上到下滑动，每滑到一个位置，就将卷积核与输入图像对应位置的元素相乘，然后将所有乘积相加，得到输出图像对应位置的值。

### 代码逐行解析

```cpp
void conv2d(
    const float** input,    // 输入图像二维数组
    const float** kernel,   // 卷积核二维数组
    float** output,         // 输出结果二维数组
    int in_h, int in_w,     // 输入图像的高度和宽度
    int k_h, int k_w        // 卷积核的高度和宽度
) {
    // 计算输出图像的尺寸：Valid模式下 out = in - kernel + 1
    int out_h = in_h - k_h + 1;
    int out_w = in_w - k_w + 1;

    // 初始化输出数组为0
    for (int i = 0; i < out_h; i++) {
        memset(output[i], 0, out_w * sizeof(float));
    }

    // 卷积核心计算：4层循环
    // 第一层：遍历输出图像的每一行
    for (int i = 0; i < out_h; i++) {
        // 第二层：遍历输出图像的每一列
        for (int j = 0; j < out_w; j++) {
            float sum = 0.0f;
            // 第三层：遍历卷积核的每一行
            for (int ki = 0; ki < k_h; ki++) {
                // 第四层：遍历卷积核的每一列
                for (int kj = 0; kj < k_w; kj++) {
                    // 最关键的一行：对应位置相乘再累加
                    // input[i+ki][j+kj]：输入图像上被卷积核覆盖的元素
                    // kernel[ki][kj]：卷积核对应位置的权重
                    sum += input[i + ki][j + kj] * kernel[ki][kj];
                }
            }
            // 将累加结果赋值给输出图像的对应位置
            output[i][j] = sum;
        }
    }
}
```

### 计算示例

输入图像（3×3）：

```
1 2 3
4 5 6
7 8 9
```

卷积核（2×2）：

```
0 1
1 0
```

计算过程：

1. 输出位置 (0,0)：覆盖输入左上角`[[1,2],[4,5]]` → 1×0 + 2×1 + 4×1 + 5×0 = 6
2. 输出位置 (0,1)：覆盖输入右上角`[[2,3],[5,6]]` → 2×0 + 3×1 + 5×1 + 6×0 = 8
3. 输出位置 (1,0)：覆盖输入左下角`[[4,5],[7,8]]` → 4×0 + 5×1 + 7×1 + 8×0 = 12
4. 输出位置 (1,1)：覆盖输入右下角`[[5,6],[8,9]]` → 5×0 + 6×1 + 8×1 + 9×0 = 14

## 编译运行原理解析

### C++ 程序编译的四个阶段

任何 C++ 程序从源代码到可执行文件都要经过四个阶段：

1. **预处理**：处理所有以`#`开头的指令，如`#include`、`#define`、`#ifndef`等
2. **编译**：将预处理后的源代码编译成汇编代码
3. **汇编**：将汇编代码转换成机器码（目标文件，`.o`或`.obj`）
4. **链接**：将多个目标文件和库文件链接成一个可执行文件

### 为什么要分离头文件和实现文件？

1. **编译效率**：当你修改了实现文件时，只需要重新编译这个文件，不需要重新编译所有包含头文件的文件
2. **代码封装**：对外只暴露头文件，隐藏实现细节，保护知识产权
3. **模块化开发**：不同的人可以同时开发不同的模块，只需要约定好头文件接口

### 直接编译 vs 静态库编译

#### 直接编译

- **原理**：将所有源文件一起编译，生成一个单一的可执行文件
- **优点**：简单方便，适合小型项目
- **缺点**：每次修改任何一个文件都要重新编译所有文件；代码无法复用

#### 静态库编译

- **原理**：先将库的源代码编译成目标文件，再打包成静态库文件（`.a`或`.lib`）。编译主程序时，只需要将主程序的目标文件与静态库链接即可
- **优点：**
  - 编译速度快：修改库代码后只需要重新编译库，不需要重新编译主程序
  - 代码复用：一个库可以被多个项目链接使用
  - 发布方便：只需要提供头文件和静态库文件，不需要提供源代码
- **缺点**：静态库会被完整地复制到可执行文件中，导致可执行文件体积较大

### 链接器的工作原理

链接器的主要任务是**解析符号引用**：

- 当编译器编译`main.cpp`时，它看到了`conv2d`函数的声明，但不知道它的具体实现，所以会留下一个未解析的符号引用
- 链接器在链接阶段会在所有目标文件和库文件中查找这个符号的定义
- 如果找到了，就将符号引用与符号定义关联起来；如果找不到，就会报 "未定义引用" 错误

## 常见问题解答

### Q1: Windows 下运行时提示 "'.' 不是内部或外部命令"

**A**: 这是因为你使用了 Linux/Mac 的运行命令`./conv_test`。Windows 下直接输入`conv_test`即可运行。

### Q2: 编译时提示 "找不到 convolution.h"

**A**: 确保`convolution.h`文件与`main.cpp`和`convolution.cpp`在同一个目录下。如果不在同一个目录，需要使用`-I`参数指定头文件的搜索路径：

```bash
g++ main.cpp convolution.cpp -o conv_test -I/path/to/header
```

### Q3: 链接时提示 "undefined reference to`conv2d (...)'"

**A**: 这是最常见的链接错误，原因是链接器找不到`conv2d`函数的实现。解决方案：

- 确保`convolution.cpp`中实现了`conv2d`函数
- 确保编译时包含了`convolution.cpp`文件，或者链接了包含该函数的静态库
- 确保函数的声明和实现完全一致（函数名、参数类型、返回值类型）

### Q4: 输出结果全是 0 或者乱码

**A**: 检查以下几点：

- 输出数组是否正确初始化
- 输入数组和卷积核的维度是否正确
- 函数参数传递是否正确（特别是高度和宽度的顺序）
